# 主动助手设计与实现约定

基于上游 `ae81b39093679a18a04049eef99f79b527cb42b8`，在个人 fork 独立分支开发。

## 产品边界

为复旦同学持续留意新邮件和校内个人安排。默认关闭；仅在 FduNav 运行（含托盘）且校园账号已登录时工作，退出、睡眠期间不能唤醒操作系统。恢复后只补一次到期检查。当前版本负责判断、解释和提醒；不会后台发送邮件、修改日历、删除数据或替用户做决定。

参考 [Dot 的任务与记忆](https://learn.chatgpt.com/docs/dots/tasks-and-memory) 和 [控制方式](https://learn.chatgpt.com/docs/dots/controls) 中持续跟进、活动记录与可暂停任务的产品理念。下面的事件机制是本项目自己的实现选择，不代表 Dot 的内部实现。

## 唤醒生命周期

1. 主进程定时器/恢复事件发出检查信号。进程内事件总线只做分发，SQLite 才是事实来源。
2. 邮箱适配器用账号 + UIDVALIDITY + UID 检查增量。首次授权/UIDVALIDITY 改变只建立基线，不回放旧邮件。每页最多 10 封，逐页推进，游标与入队在同一事务内写入。
3. 每个监控最多一个待处理/运行任务，全局单 worker；定时触发合并。持久化队列重启后继续，未完成运行标记中断并有限重试。
4. 每次运行构建全新上下文，调用只读判断器（无工具权限），严格校验结构化决定与来源引用。
5. 无事可做只写活动；需要关注才进入关注列表并发出可选系统提醒。系统通知只显示通用文案，锁屏不泄露邮件内容。
6. 配置修改、账号改变、停用 LLM、应用退出取消请求；过期结果不能提交。临时失败有限重试，永久失败可手动重试。不会把“读取失败”当作“无需关注”。

## 上下文协议 v1

- 控制层：固定系统提示，明确数据不可信、禁止执行来源中的指令，输出 JSON 契约。
- 本次任务：监控目标、当前时间/时区、触发原因；仅此监控上次成功的简短检查结论（不共享其他监控的私有笔记）。
- 来源层：新邮件正文节选；或未来七天日程和未完成待办。用户另行选择是否加入相关、未过期的已启用个人记忆。
- 每封邮件最多 1800 字，每次最多 10 封；日程/待办各最多 20 项，记忆最多 6 条；总上下文硬上限 28000 字。每条来源有短引用和独立截断标记，整体报告覆盖缺口。
- 模型不接收邮件连接参数、密码、Cookie、原始响应、数据库对象、无关聊天或历史工具轨迹。时间与截断元数据属于判断必要信息。
- 每次独立推理；前次摘要最多 600 字，不能增加权限，不能取代原始来源。没有自动写入长期记忆的路径。
- 活动存储来源 ID、计数、摘要和上下文摘要哈希，不落盘邮件正文或完整请求。摘要可能包含个人信息，保存在本机用户数据目录；可清空记录，自动保留 30 天/最多 200 条。邮箱游标独立于活动清除。

## 预算、取消和故障

每次运行硬截止 90 秒，模型调用最多一次逻辑请求（连接层对瞬时网络失败已有有限重试），输出上限与严格 JSON 校验；默认每日最多 24 次模型检查，可设 1–100 次。无新邮件不调用模型。达到预算保留队列，次日继续。邮件读取失败不推进消费游标；正文不完整显式报告，禁止用缺失证据断言无需处理。错误展示稳定、安全的阶段信息，不暴露原始堆栈或远端返回正文。关闭总开关会取消待处理任务，重新开启邮箱监控重新建立基线。

## 后续扩展

事件、持久化队列、上下文构建、决策器、平台通知与 UI 分离。后续可增加通知公告/教学大纲来源，以及“建议建待办 → 用户审批 → 幂等执行”的工具权限层；不能直接把手动聊天的写工具赋予后台 worker。当前定时监控只读取本地日历/待办，不会联网搜索、同步 eHall 或自动刷新 eLearning。
